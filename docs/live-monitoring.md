# 期货与期权后台盘口监控

入口：主系统 `/live` 的「期货后台监控」和「对应期权与监控」。创建任务后由 market-service 调度，关闭页面、退出浏览器或暂停页面刷新均不会暂停任务；停止任务需点击任务的「暂停」。列表、触发记录和已读状态由当前租户共享，归档保留历史。

## 对应期权

期货主连先根据行情源元数据解析实际交割合约，再按期权的真实 underlyingSymbol 精确匹配期货期权链。可以筛选到期日、认购／认沽、行权价和具体合约。没有匹配链时显示空状态，不替换其他交割月。自动选择平值附近合约需要真实标的价格，也可以手动选择。

期权支持与期货相同的九种显示周期及 MA5/10/20/60/180。盘口每 2 秒读取、K 线每 3 秒读取；显示真实买卖档位与近期 Tick 成交增量。缺失档位和不足历史的均线留空，过时数据标明缓存。

## 规则与依据

算法版本为 `depth-monitor-v1`。技术监控周期支持 1、3、5、15 分钟，独立于页面显示周期。所有技术规则仅使用已有后继 K 线证实收盘的完整柱；正在形成的最后一根不参与触发。仅处理新确认且近时的柱，首次建立基线不补发历史信号。

| 规则 | 判断方式与默认参数 |
| --- | --- |
| 60 秒涨／跌幅 | 从服务器实际观察的报价建立滚动窗口，涨跌严格超过 10%；支持调整阈值。需先积累至少 60 秒数据，使用最近 60 秒内最早的观察报价（距窗口左端最多 10 秒），不计入窗口外的价格变化。依据中记录实际观察秒数。数据间断超过 15 秒重新预热。 |
| 大额买／卖向成交增量、方向未定的大额增量 | 单个新 Tick 的累计成交量增量达到手数阈值；期货界面默认 100 手、期权 20 手。独立 Tick 去重，不因常规冷却丢弃不同的大额增量。 |
| 成交量异动 | 当前完整柱成交量达到此前 20 根平均量的 2 倍，回看长度、倍数可调。历史均量为零时不计算比值。 |
| 放量突破前高／前低、唐奇安上下轨 | 满足放量条件，收盘价从阈值内跨越此前 N 根最高／最低价。 |
| 放量突破／跌破均线 | 满足放量条件，前后完整柱的收盘价相对各自 MA 发生跨越；可选择 MA5/10/20/60/180，完整窗口不足时不计算。 |
| 放量突破布林上下轨 | 前 N 根收盘价均值 ± 2 倍总体标准差；满足放量条件且价格跨轨，倍数可调。 |
| 放量突破肯特纳上下轨 | 上一完整柱 EMA(N) ± 2 倍此前 N 个真实波幅的算术均值，满足放量和跨轨条件。真实波幅包含与前收盘价的跳空；倍数可调。 |
| MACD 金叉／死叉 | DIF=EMA12−EMA26，DEA=EMA9(DIF)，仅确认完整柱的穿越。 |
| MACD 底／顶背离 | 价格出现两个严格低／高枢轴，间隔至少 5 根、前枢轴在最近 100 根范围内。底背离为价格更低而 DIF 同为负且抬高；顶背离反向且 DIF 同为正。默认枢轴右侧需 2 根完整柱确认，可调 1–5 根；记录两个枢轴及确认依据，避免回看提前报信。 |
| ATR 价格异动 | 完整柱收盘变化绝对值达到此前 N 个真实波幅均值的 2 倍，可调。 |
| 可见挂单失衡 | 可见买卖挂单量之差占总量的绝对值跨过 60%，记录方向及数量。 |
| 买卖价差异动 | 当前买卖一价差至少达到此前最多 20 个有效观察样本均值的 3 倍，至少积累 10 个样本。 |

共有 23 种可选条件；均线规则分别记录所触发的 MA。技术及涨跌类默认每个规则／变体冷却 60 秒，可调 10–3600 秒。记录包含规则、合约、源时间、保存时间、算法版本及原始计算依据，可搜索、按任务筛选、只看未读和分页。

Tick 是行情快照中的成交量增量，可能包含多笔成交。买卖方向由价格和买卖一估算；大额买／卖向增量不代表逐笔委托、大单撤挂或交易者身份。这里的异动是明确的量价规则，不涉及自动交易。

## 数据、运行与权限

- 报价或图表过时超过 15 秒、缓存、断线、缺失有效价格、时间异常均抑制触发。启动、重连、配置修改和暂停恢复重新建立所需基线，不回放旧 Tick。休市通常显示 `STALE`，不反复生成相同提示。
- 主连创建时绑定解析出的实际交割合约，列表会显示绑定结果，后续不自动换月；到期的期权任务自动停用。需要换月时为新合约建立监控。
- 由最后保存或启用任务的用户授权执行。每次求值前核验账号、邮箱验证状态、租户成员身份以及相应 `market.read/write` 或 `options.read/write` 权限；撤权后为 `FORBIDDEN`，恢复权限后可继续。租户停用同样生效。
- Gateway 使用当前登录态／API 令牌及 CSRF 规则，私有服务核验签名身份。数据库对任务、事件和配置审计启用 FORCE RLS；跨租户及跨期货／期权接口不可读写其他记录。
- 每租户最多 20 个启用任务，全局最多 32 个；后台并发 4 个。一般每次完成求值后至少间隔 3 秒，下游耗时可能延长间隔，页面可查看最近检查和源时点。不是交易所逐 Tick 推送保证。
- 行情采集仍由单个 SDK 线程负责，期权盘口／Tick 最多 32 个不同订阅；K 线复用现有 48 组订阅上限。达到容量时明确报错，不静默替换合约。
- 调度使用数据库租约、状态持久化及事件唯一键，重启后恢复；暂停／修改后的过期求值结果不能入库。状态更新与事件保存处于同一事务。
- 任务变更另存租户内配置审计；触发记录和配置审计目前不自动清理，应由部署方制定保留与备份策略。这里只提供站内记录，无外部邮件／聊天提醒。

## 部署与接口

现有 ai-quant Compose 使用共享 `IDENTITY_INTERNAL_SECRET`，market-service 增加 `IDENTITY_SERVICE_URL`，服务启动自动应用 market V2 迁移。迁移前备份 PostgreSQL，更新 identity-service、algorithm-service、market-service、gateway-service、frontend。不要重置现有管理员密码。

- 期权读接口：`GET /api/v1/options/linked?future=RBM`、`/contracts?chainId=...`、`/depth?symbol=...`、`/chart?symbol=...&seconds=60`，日周月通过 `period=DAY|WEEK|MONTH`。
- 监控基础路径：`/api/v1/market/monitors`、`/api/v1/options/monitors`。GET 基础路径／`catalog`／`{id}`／`events`；POST 基础路径创建、`{id}` 修改、`{id}/enabled` 暂停恢复、`{id}/archive` 归档、`events/{id}/ack` 已读。写请求携带版本，冲突返回 409。
- `/internal/v1/monitor/*` 及 identity 的后台授权接口仅供服务间调用，使用共享密钥，不在公网 Gateway 暴露。
