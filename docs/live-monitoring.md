## 结果反推的条件概率预警（2026-11-07）

最新版本 `depth-monitor-v4`，完整报告见 [活跃期货结果反推实验报告](research/outcome-first-2026-11-07.md)，可阅读 PDF 在 `output/pdf/active-futures-outcome-study-2026-11-07.pdf`。这次以历史结果标签反推事前特征，而非只验证预设形态。

主源采集34个活跃品种（此前20个完整日线成交量中位数≥10,000手），173,560根原始15分钟柱，生命周期清洗后155,515根，形成87,976个带结果标签的截面。26个品种拟合、8个品种从本次模型中留出；再按时间分开发、7–9月检验和10月后比较。截面标签有重叠，不冒称独立交易笔数。

新增「结果反推 · 概率预警」模板，固定15分钟特征，可选入场窗口、离场风险、拐点、方向或全部；可选只发概率改善候选，或包含品种／阶段依赖条件。数据不足、非活跃范围、期权或非15分钟不作模型推断。首次建立基线，不回放旧信号；在新柱确认附近匹配已完成柱，只调用事前特征，不调用未来标签函数。

历史标签包含未来走势，实时特征不含未来。预警保存匹配路径、当时特征、特征／确认／可得时点和各检验阶段的条件频率、对照、样本及费用后观察结果。局部低点转折等标签较稀少，14%的标签频率不表示86%的交易必亏。概率改善与成本后期望分层展示，不要求100%成功，也不把概率改善宣传成自动交易盈利。

最新接口 catalog 的 `outcomeResearch` 提供冻结模型和研究摘要；任务参数新增 `outcomeTarget`、`outcomeEvidence`。不会把旧任务自动转成概率预警，需选择合约、模板、保存并启用。每分钟盘口留档已下线；没有自动开平仓。

## 实时入场／出场条件预警（2026-11-07）

进一步统计研究及接入见 [趋势与机会三轮检验](research/trend-opportunities-2026-11-07.md)。当前执行版本 `depth-monitor-v3`，新增日线趋势／拐点研究预警和对应条件的统计资格；本批没有候选取得稳健交易资格。

用户确认口径：20 日线是日线 MA20，突破等 15 分钟 K 线收盘确认，回踩 MA5 支持盘中接近／触及。入口为实时看盘「期货机会预警」，选择合约后点击模板，保存并启用。旧盘口规则按上文下线迁移处理。

- **15 分钟突破／跌破日线 MA20**：以前 20 根已完成日线的收盘均价作为日线参考，已确认收盘的 15 分钟 K 线由均线下方穿到上方时记录做多入场观察；反向记录多头退出／做空观察。不强制附加放量条件。参考均线不纳入正在形成的日线，区别于图上随盘中价格变化的当日日线均线。
- **日线回踩 MA5**：以前 5 根已完成日线计算参考线，服务器实际观察到价格从均线上方接近到容差区间时提示。默认容差 ±0.2%，可改为 0 做严格触及；价格直接跳过区间不补造触及。提示明确标记「盘中触及 · 未确认」，不代表支撑已有效。模板同时启用 15 分钟收盘跌破该日线均线的退出／做空观察。

均线天数可设 2–180；分钟确认周期可设 1／3／5／15 分钟。规则名称中的日线指参考周期，任务分钟周期指突破确认周期。日线未就绪、过时、历史不足或合约不一致时跨周期预警暂停并显示预热状态，不退回当前分钟图的 MA 冒充日线 MA。首次启动、报价中断后恢复及日线参考换日重新建立观察基线，不补发旧信号。持续停留同一侧不重复发突破，盘中回踩按观察到的新接近及冷却去重。

触发列表展示机会方向、确认类型、价格、日线均线值及源时间；可打开判断依据和对应合约 K 线。历史告警只用于复核当时条件，不代表当前仍可入场。当前提供站内预警记录，页面打开时自动刷新；没有增加外部消息推送或自动下单。旧量价扫描规则已下线，其纯计算函数保留用于历史研究复现。

补充验证：跨周期规则、缺失／过时／未来日线抑制、盘中触及去重、收盘穿越与参考切换等 Python 用例和既有规则合计 24 项通过；前端模板参数、触发依据、历史及看盘相关 23 项检查通过，生产构建通过。真实开市中的新规则触发尚未作为验收依据。

## 历史盘口监控（已下线，以下为原实现记录）

`/live` 新增「历史盘口监控」。先在「期货后台监控」启用一个或多个合约任务，服务器持续检查并每 60 秒保存一份结果，页面关闭不影响执行。沿用原监控的短周期采样以计算连续的 60 秒涨跌窗口；历史保存至少间隔 60 秒，实际执行可能因服务负载或行情超时延后。停机期间不补造记录，恢复后继续采样。

每份记录冻结任务名称、配置与版本、技术周期、源时间、检查时间和状态。未触发、窗口预热、休市过时、断线及授权失败也留档。正常行情保存最新价、完整柱成交量、相对此前 N 根均量的柱量比、60 秒涨跌、MA5/10/20/60/180、MACD DIF/DEA/双倍柱值、布林上下轨、ATR、可见买卖挂单量、盘口失衡与买卖价差。所有技术指标只用存在后继柱的完整 K 线；窗口不足返回空值，不用零代替。

支持合约／任务名称搜索、分页与检查详情。详情的 signals 仅包含该次检查触发的条件；连续三秒检查中的全部告警仍查原触发记录，历史快照不宣称汇总了整分钟每笔成交或完整告警。行情过时的记录不沿用旧指标冒充新值。参数中的规则列表仍控制告警条件。

新增 `market` V3 表 `live_monitor_history` 及每任务历史保存水位。历史保存与监控结果提交同一事务，沿用任务租约及版本校验；暂停／修改后返回的过期结果不能写入历史。FORCE RLS 隔离租户，列表还按期货／期权隔离；只给租户角色历史 SELECT 权限。归档任务保留历史，不在运行数据自动归档工具的允许裁剪范围内。

接口为 `GET /api/v1/market/monitors/history?q=&monitorId=&page=1&size=20`（期权使用 options 前缀），沿用登录态及读取权限。部署更新 algorithm-service、market-service、frontend，迁移前备份 PostgreSQL。历史从功能部署并启用任务后开始产生。

本轮验证：Python 规则测试 19 项、相关前端测试 22 项及生产构建通过；真实隔离 PostgreSQL 中 market-service 的 20 项测试（含 10 项监控存储集成检查）全部通过，另租户签名测试 1 项通过。Docker Java Reactor 构建通过，普通构建中需要其他专用数据库的用例仍跳过。部署后已有的一个期货任务连续写入真实快照，首两条间隔 61.301426 秒，分别为预热／过时状态；这证明后台留档运行，不作为开市稳定性或完整指标实盘验收。19 个原模拟会话保留。本轮未进行登录后的浏览器视觉验收，测试记录见 `docs/research/data/minute-monitor-history-2026-11-07/`。

## 对应期权行情

期货主连先根据行情源元数据解析实际交割合约，再按期权的真实 underlyingSymbol 精确匹配期货期权链。可以筛选到期日、认购／认沽、行权价和具体合约。没有匹配链时显示空状态，不替换其他交割月。自动选择平值附近合约需要真实标的价格，也可以手动选择。

期权支持与期货相同的九种显示周期及 MA5/10/20/60/180。盘口每 2 秒读取、K 线每 3 秒读取；显示真实买卖档位与近期 Tick 成交增量。缺失档位和不足历史的均线留空，过时数据标明缓存。

## 旧盘口规则与依据（已下线，保留复现定义）

原有技术量价规则沿用 `depth-monitor-v1` 的定义，本次执行版本为 `depth-monitor-v2`。技术监控周期支持 1、3、5、15 分钟，独立于页面显示周期。下表的技术规则仅使用已有后继 K 线证实收盘的完整柱；正在形成的最后一根不参与触发。仅处理新确认且近时的柱，首次建立基线不补发历史信号。新增跨周期的盘中回踩条件另见上文，明确标为未确认。

| 规则 | 判断方式与默认参数 |
| --- | --- |
| 60 秒涨／跌幅 | 从服务器实际观察的报价建立滚动窗口，涨跌严格超过 10%；支持调整阈值。需先积累至少 60 秒数据，使用最近 60 秒内最早的观察报价（距窗口左端最多 10 秒），不计入窗口外的价格变化。依据中记录实际观察秒数。数据间断超过 15 秒重新预热。 |
| 大额买／卖向成交增量、方向未定的大额增量 | 单个新 Tick 的累计成交量增量达到手数阈值；期货界面默认 100 手、期权 20 手。独立 Tick 去重，不因常规冷却丢弃不同的大额增量。 |
| 成交量异动 | 当前完整柱成交量达到此前 20 根平均量的 2 倍，回看长度、倍数可调。历史均量为零时不计算比值。 |
| 放量突破前高／前低、唐奇安上下轨 | 满足放量条件，收盘价从阈值内跨越此前 N 根最高／最低价。 |
| 放量突破／跌破均线 | 满足放量条件，前后完整柱的收盘价相对各自 MA 发生跨越；可选择 MA5/10/20/60/180，完整窗口不足时不计算。 |
| 放量突破布林上下轨 | 前 N 根收盘价均值 ± 2 倍总体标准差；满足放量条件且价格跨轨，倍数可调。 |
| 放量突破肯特纳上下轨 | 上一完整柱 EMA(N) ± 2 倍此前 N 个真实波幅的算术均值，满足放量和跨轨条件。真实波幅包含与前收盘价的跳空；倍数可调。 |
| MACD 金叉／死叉 | DIF=EMA12−EMA26，DEA=EMA9(DIF)，仅确认完整柱的穿越。 |
| MACD 底／顶背离 | 价格出现两个严格低／高枢轴，间隔至少 5 根、前枢轴在最近 100 根范围内。底背离为价格更低而 DIF 同为负且抬高；顶背离反向且 DIF 同为正。默认枢轴右侧需 2 根完整柱确认，可调 1–5 根；记录两个枢轴及确认依据，避免回看提前报信。 |
| ATR 价格异动 | 完整柱收盘变化绝对值达到此前 N 个真实波幅均值的 2 倍，可调。 |
| 可见挂单失衡 | 可见买卖挂单量之差占总量的绝对值跨过 60%，记录方向及数量。 |
| 买卖价差异动 | 当前买卖一价差至少达到此前最多 20 个有效观察样本均值的 3 倍，至少积累 10 个样本。 |

共有 23 种可选条件；均线规则分别记录所触发的 MA。技术及涨跌类默认每个规则／变体冷却 60 秒，可调 10–3600 秒。记录包含规则、合约、源时间、保存时间、算法版本及原始计算依据，可搜索、按任务筛选、只看未读和分页。

Tick 是行情快照中的成交量增量，可能包含多笔成交。买卖方向由价格和买卖一估算；大额买／卖向增量不代表逐笔委托、大单撤挂或交易者身份。这里的异动是明确的量价规则，不涉及自动交易。

## 数据、运行与权限

- 报价或图表过时超过 15 秒、缓存、断线、缺失有效价格、时间异常均抑制触发。启动、重连、配置修改和暂停恢复重新建立所需基线，不回放旧 Tick。休市通常显示 `STALE`，不反复生成相同提示。
- 主连创建时绑定解析出的实际交割合约，列表会显示绑定结果，后续不自动换月；到期的期权任务自动停用。需要换月时为新合约建立监控。
- 由最后保存或启用任务的用户授权执行。每次求值前核验账号、邮箱验证状态、租户成员身份以及相应 `market.read/write` 或 `options.read/write` 权限；撤权后为 `FORBIDDEN`，恢复权限后可继续。租户停用同样生效。
- Gateway 使用当前登录态／API 令牌及 CSRF 规则，私有服务核验签名身份。数据库对任务、事件和配置审计启用 FORCE RLS；跨租户及跨期货／期权接口不可读写其他记录。
- 每租户最多 20 个启用任务，全局最多 32 个；后台并发 4 个。一般每次完成求值后至少间隔 3 秒，下游耗时可能延长间隔，页面可查看最近检查和源时点。不是交易所逐 Tick 推送保证。
- 行情采集仍由单个 SDK 线程负责，期权盘口／Tick 最多 32 个不同订阅；K 线复用现有 48 组订阅上限。达到容量时明确报错，不静默替换合约。
- 调度使用数据库租约、状态持久化及事件唯一键，重启后恢复；暂停／修改后的过期求值结果不能入库。状态更新与事件保存处于同一事务。
- 任务变更另存租户内配置审计；触发记录和配置审计目前不自动清理，应由部署方制定保留与备份策略。这里只提供站内记录，无外部邮件／聊天提醒。

## 部署与接口

现有 ai-quant Compose 使用共享 `IDENTITY_INTERNAL_SECRET`，market-service 通过 `IDENTITY_SERVICE_URL` 核验执行权限。服务启动自动应用至 market V4 迁移。迁移前备份 PostgreSQL，本次更新 algorithm-service、market-service、frontend 并重建网关以刷新地址。不要重置现有管理员密码。

- 期权读接口：`GET /api/v1/options/linked?future=RBM`、`/contracts?chainId=...`、`/depth?symbol=...`、`/chart?symbol=...&seconds=60`，日周月通过 `period=DAY|WEEK|MONTH`。
- 监控基础路径：`/api/v1/market/monitors`、`/api/v1/options/monitors`。GET 基础路径／`catalog`／`{id}`／`events`；POST 基础路径创建、`{id}` 修改、`{id}/enabled` 暂停恢复、`{id}/archive` 归档、`events/{id}/ack` 已读。写请求携带版本，冲突返回 409。
- `/internal/v1/monitor/*` 及 identity 的后台授权接口仅供服务间调用，使用共享密钥，不在公网 Gateway 暴露。
