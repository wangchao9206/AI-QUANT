# 计划对模拟开仓的服务端约束

本阶段从基线 `02a7cff` 继续 P0，2026-11-07 开始，2026-11-08 完成发布核对。目录沿用开始日期。目标是让私人计划、关联模拟账本与实际模拟委托产生约束关系，而不是只提供回链。

## 实现范围

- V14 为模拟账户增加服务端 `decision_guarded` 标识，回填已有计划关联；新建计划账户自动标记。私人关联不可读取时不会回退为普通账户。迁移不修改既有订单、成交和持仓。
- 新增 OPEN 在插入订单前检查：计划本人及行情权限、最新保存版本、有效期、同一实际交割月、手动 LIVE 模式、禁止自动换月、行情与核验时点均在过去30秒至未来2秒之间、规格未变化、价格跳动对齐、方向、合计手数、风险预算、保证金及费用。
- 报价、限价/触发价及实际成交价必须严格位于保护价和目标价之间。入场价是风险估算参考，不是自动执行触发器，也不强制只能在这一价格成交。
- 持仓和所有 PENDING/PARTIAL 开仓剩余数量共同占用额度。会话行锁使并发请求串行核验；计划档案共享锁与保存版本互斥，取锁后用数据库实际时钟再次核验时效。
- 每次刷新准备撮合开仓挂单时重新检查；实际成交使用本次不利成交价重新试算，部分成交后的未成交部分继续占用预算。撮合不通过的订单记为 REJECTED 并保存原因，不生成成交。提交前被拒绝的请求返回403/409，不插入虚假订单。
- 保存新版本后，旧版本账户停止新增开仓；旧开仓挂单在本人下一次可交易行情刷新核验时拒绝。非交易时段保留挂单，直到后续有效核验，不承诺后台自动撤单。
- CLOSE 沿用原账户状态、真实报价、持仓和方向检查，不受计划过期、修订或行情读取权限变化的新增开仓门槛限制；平仓提交不会顺带执行开仓挂单。撤单释放未成交部分的占用。
- 原有普通账户、历史回放、策略账户和个人训练保持各自规则。计划账户不会因主力变化而静默换月。

## 权限与隐私

模拟账本仍在工作空间内共享，计划、关联、私人复盘继续 FORCE RLS 的 tenant+owner 隔离。普通模拟接口现在从经过签名验证的身份设置本事务 owner，GET 要求 paper.read，变更要求 paper.write；没有新建可绕过 RLS 的数据库函数。

仅具备行情权限的计划本人可新增开仓并触发开仓挂单撮合。其他成员或缺少行情权限的本人刷新时，跳过这些开仓挂单，既不执行，也不因读不到私人计划而错误拒绝。已有平仓/撤单权限保留。不可读取计划时，账户详情仅说明受私人计划约束，不返回方向、预算、手数或计划ID。

列表仅增加是否受约束的标识；详情增加 `planGuard`。其中 `openingAllowed` 仅表达当前身份、版本和有效期的静态门槛，行情、资金和预算仍在每次提交/撮合时检查。界面明确说明重新核验，不把它当成可交易资格证明。

身份、工作空间或实际权限集合发生变化时，页面实例重新建立，清除上一身份的计划额度和草稿等路由内缓存；仅权限排列顺序变化不会丢弃当前页面。旧页面的迟到结果不复用到新页面，模拟页销毁后不再继续恢复旧账户的路由。

## 风险与资金口径

所有价格和金额使用 BigDecimal。设方向 d 为多头+1/空头-1，合约乘数 M，保护价 S，配置的不利滑点量 δ。保护价情景成交价为 S*=S−dδ，并按不利方向对齐最小跳动。

单份敞口的保护价情景损失为 `max(d × (入场价−S*), 0) × M × 手数`，另计未来手续费。总风险占用是：

1. 账户全部历史成交中每笔负 realized_pnl 的绝对值之和，以及全部已付手续费；盈利不冲抵已经发生的亏损。
2. 当前持仓按实际平均入场价计算的保护价情景损失，以及预留平仓费。
3. 全部开仓挂单剩余数量的保护价情景损失，以及预留开仓费和平仓费。

待成交入场参考选计划入场、当前报价、该单限价/触发价中对方向较不利者；MARKET/STOP 再加配置的不利开仓滑点，LIMIT 沿用原引擎不增加成交滑点的规则。撮合时，本次成交部分替换为真实模拟成交价，未成交部分保留保守预留。手续费取固定每手佣金与按成交额费率的较大者，并沿用账本舍入规则。

总手数为当前持仓加全部开仓剩余数量；总保证金按各份敞口的 `max(合约每手保证金, 价格×乘数×账户保证金率)` 累计，并预留开仓费，不能超过当前现金加按本次报价计值的未实现盈亏。盈利可以影响真实可用资金，但不能抹去上述已发生亏损的风险占用。

这是该独立计划账户的情景约束，不计外部账户或其他计划账户的敞口。保护价不会自动触发平仓；没有新增止损/止盈执行器，也没有保证损失上限，跳空与滑点可能使实际损失超过情景预算。不得把这项软件约束视为策略有效性、概率预测或盈利证明。

## 复跑与发布

只在无业务数据卷的临时 `paper_test` 数据库中设置 PAPER_TEST_JDBC_URL 并运行测试，测试会清空隔离库 schema，禁止指向正式数据库。Java17 下运行 `mvn -s maven-settings.xml -pl paper-trading-service -am test`；前端运行 `npm test` 与 `npm run build`。

浏览器设置 PLAYWRIGHT_MODULE 与 PLAN_GUARD_UI_URL，运行 `node scripts/qa_plan_order_guards.cjs`。发布前运行 `python scripts/verify_plan_order_guard_deployment.py --snapshot`，发布后去掉参数运行只读检查。只构建和替换 paper-trading-service/frontend，保留原部署模式和数据卷；identity-service镜像保持不变。镜像构建附带的未配置隔离库测试不能替代上面的实际数据库集成测试。

回退镜像见pre-deploy.json；V14是加列及标记回填，可保留，不应删除账本。旧服务没有本轮开仓约束，回退时需同步停止计划账户新增开仓，不能继续宣称保护有效。

本阶段完成计划与模拟委托的基础约束，整体重构仍未全部完成。专业期权/缠论工作区的上下文统一、布局偏好、私人画线跨设备恢复，以及后续预测、指标、策略与辅助决策契约仍需继续实施；此前的大样本研究要求不能由本轮功能测试代替。
