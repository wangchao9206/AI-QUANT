# 交易决策档案空白页修复

2026-11-07，针对用户报告的“交易决策档案是空白页面”完成复现、修复和本地 8088 部署。

## 原因与修复

Vue Router 对 `/paper/decisions/:id?` 缺省的 `id` 返回空字符串。旧逻辑只检查字符串类型，错误地进入详情分支，向 `/api/v1/paper/decisions/` 发起请求。此前的接口别名修复已使该地址返回正常列表，但页面把列表信封赋给了详情状态，随后渲染 `item.origin.id` 抛出异常。

上一轮覆盖了详情页，漏测了无 ID 的目录入口。此次在修改前用已部署的完整应用与实际路由复现了异常，堆栈与请求保存在 `before-fix.json`。

现在只有非空 ID 才请求详情；无 ID 时请求分页列表。在详情加载、计划保存和复盘响应赋值前检查详情结构，在列表赋值前检查分页结构。错误对象不会进入页面状态。空列表保留说明与行情/研究入口，异常显示可重试的错误。

此次只更新前端，没有数据库迁移，也没有创建用户或填充虚假档案。

## 复跑

设置 `PLAYWRIGHT_MODULE` 为可用的 Playwright 模块路径（或已安装的 `playwright`），设置 `DIRECTORY_UI_URL=http://127.0.0.1:8088`，运行 `node scripts/qa_decision_directory.cjs`。默认使用 Windows Edge；可通过 `PROTOTYPE_BROWSER` 指定浏览器程序。脚本不写入业务数据库，但会更新本目录的验收 JSON 和截图。
