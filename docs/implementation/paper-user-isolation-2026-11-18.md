# 模拟账户按创建用户隔离

## 原因和修复

原模拟账本只有 tenant_id 限制。admin 和 test 同属默认工作空间，因此管理员身份能访问同一租户中的全部模拟数据。

V18 在原租户 RLS 上增加不可被其他宽松策略绕过的用户所有权条件。账户的持仓、委托、成交、分钟档案、成交心得、自动策略及其日志、个人训练均继承父账户的可见性。独立复盘和个人策略版本也按用户隔离。OWNER、ADMIN 均不能通过角色访问其他人的私人模拟账户。

请求事务只从验证过签名的内部身份取 userId，并以事务内 app.user_id 传给数据库。用户提交的 ownerId 不决定归属。后台任务继续以运行创建者身份执行；旧运行身份不匹配账户归属时停止执行并撤销其未成交挂单，保留已有持仓。

默认个人策略版本的 ID 按租户、用户、引擎共同生成，避免同租户两个用户争用原固定版本 ID。

## 历史数据

先备份整个 paper_trading，再通过唯一的成功创建请求审计回填所有权。现有五个模拟账户均确认由 admin 创建，test 创建时间晚于这些账户。不确定归属的旧数据保留但隐藏，不按最近访问人分配。

事务性热修复已核对账户 ID、资金、累计盈亏、费用、成交/委托 ID、持仓及心得数量，原始账本保持一致。连接池重启以清除新增列之前缓存的结果类型。

## 验证

独立临时 PostgreSQL 的 25 项集成回归通过，包括同租户两用户的列表、直接 ID 读取、图表、流水、下单、撤单、暂停、删除、心得、自动策略启停、个人版本/复盘隔离，以及原有回放、共同资金账户和私人决策流程。

真实数据库受限角色检查：默认租户 admin 可见 5 个原账户，test 可见 0 个原账户。网页端验收使用独立临时租户的 OWNER 和 ADMIN，不修改真实用户的密码或角色。

验收脚本：scripts/qa_paper_owner_isolation.cjs。临时身份工具支持 create-peer，clean 只清理工具持有 UUID 的临时身份及其专用租户。

Docker 部署后的真实网页/API 验收已通过：同一租户的 OWNER、ADMIN 各自创建账户；相互直接 ID 读取和修改均被拒绝；成交心得、个人策略默认版本和独立复盘均私有；同一浏览器退出再登录不显示前一用户账户；原创建人仍能读取原账户、心得并停止策略。

启动刷新也已在真实天勤数据中连续验证两次：每次启动都有不同 requestKey 和新的完成时间，均重新下载 443 根日线、600 根分钟线；保留行情源原时间，休市期间没有下单。
