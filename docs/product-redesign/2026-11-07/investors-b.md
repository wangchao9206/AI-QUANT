## P05 八年经验的日内交易者

人物设定是假设：熟悉两三个流动性较好的期货品种，盘中使用多周期和盘口确认；重视响应速度和风险处置，愿意自行下判断，不希望接收大量无关预测。具体资金规模、真实胜率及交易频率未设为事实。

### 问题一：典型任务和限制是什么

**访谈员：** 假定你在开盘前后使用这个产品，首要任务是什么？

**模拟回答：** 先看我关注品种有没有事件风险和异常跳空，再守几个预先定义的条件。触发后我要迅速定位“哪个实际合约、哪个周期、哪根已完成K线”，判断现在还有没有追价空间。我的限制是注意力和执行窗口，不是缺少更多指标。

**追问：** 如果系统现在还没有验证出优势，你仍会用什么？

**模拟回答：** 会用可靠图表、可解释预警、风险核算和复盘。不要把一个日线分数包装成我下一笔短线的胜率。

**判读：** 场景是角色假设；B02/B05确认产品已有相应数据与风险字段。是否把预警延迟视为首要问题，仍需真人观察，不能由本模拟量化其权重。

### 问题二：从当前产品哪里开始，会在哪里卡住

**访谈员：** 依据当前页面结构，你会从哪里开始？

**模拟回答：** 默认会到“实盘看盘”，而不是先翻总览、线索池、策略、自主研究。我能在那里看K线、盘口和后台任务，已有预警查看合约也有价值。问题是，我看完触发依据跳回图，仍要自行重找当时的柱和线；切到期权或模拟后，还要再确认合约、时点和持仓情景是不是同一个。

**追问：** 是否应删除所有其他入口？

**模拟回答：** 不应。盘中只收起不用的东西。回测和研究在盘后仍有价值；不要把我的盘中屏幕变成研究报告目录。

**事实与假设：** B01/B02证明入口和合约定位函数现状；“重找导致决策迟疑”是待验证的体验推断，不是已经测量的错误率。

### 问题三：预测冲突或证据弱时需要什么

**访谈员：** 日线偏多、15分钟下破、盘口买向占比较高，应给你一个综合买入分吗？

**模拟回答：** 不要把三个时间尺度硬平均。先显示我计划使用的周期与失效条件，再显示其他尺度是支持还是冲突。盘口估算的买向不等于主动买盘真相，更不能覆盖已经触发的止损条件。

**追问：** 如果只剩弱证据？

**模拟回答：** 把它放在“观察”而不是“可执行”。我仍可自行交易，但系统要把当时我忽略了什么保存下来，之后才有复盘价值。

**事实与假设：** B03/B05支持区分规则与已验证概率；分层冲突处理是设计建议，不是当前已有的统一功能。

### 问题四：跨模块必须带哪些字段

**访谈员：** 从预警到图表、计划和模拟，哪些信息不能丢？

**模拟回答：** 原始实际合约及请求时的主连映射、周期、触发事件ID、K线起止与确认时间、数据状态、规则/模型版本、当时的线和阈值。我建立计划后，还应带计划ID、有效期、最大风险、入场与失效价、是否已有仓位。如果再开了模拟单，成交应回链到这份计划和触发，而不是靠我事后写备注。

**追问：** 实时图和历史触发快照冲突怎么办？

**模拟回答：** 同一页面能切“当时/现在”。当时的线要冻结，现在的线可以更新，不能让我误以为后画出来的线当时就存在。

**事实与假设：** B02/B05有部分字段和局部链接；统一 `decisionCaseId`、事件至成交关系与双时间视图均是提议，不是已实现能力。

### 问题五：模块如何取舍

**模拟回答：** 保留一个看盘工作区，市场列表、自选、机会队列在里面切换。线索池、盘中提示和不同策略预警应该共用一份可筛选事件队列，但不要把日线和盘中触发混为同一个强度。缠论、自动线和普通指标作为图层/方法配置；学习、书籍、人物解读收进资料区。系统管理不占交易主导航。回测保留独立盘后空间，别塞进每根K线边上。

**与其他角色的潜在冲突：** 他要低噪声与快速确认，可能排斥新手所需的逐步解释；其“只关注少数品种”也不能替代跨市场量化筛选。

### 问题六：理想流程和可验收场景

**模拟回答：** 我从自选队列点一个触发，主图立即定位原合约、原周期、原柱、原线；核对当时与现在后，把它转成带有效期的计划；模拟下单确认只读同一份计划，成交后复盘自动看到偏离项。

**建议验收，非已测结果：** 对固定的10个隔离历史事件，逐项核对合约、周期、时间、阈值、模型版本和线锚点；预警到计划到模拟全过程不需重选这些字段。失效/过时事件不得直接作为新的可执行计划；关闭浏览器后后台任务状态保持真实。业务数据不因验收被写入测试成交。

| 需求ID | 建议优先级 | 需求与可证伪假设 |
| --- | --- | --- |
| P05-N1 | P0 | 预警点击保留原事件上下文与原图快照。真人测试若不需要回看原柱，而只看当前价格，应重新评估默认布局。依据B02，缺口为推断。 |
| P05-N2 | P0 | 统一机会队列按时间尺度/来源去重，不用一个综合分吞掉冲突。若不同来源其实支持独立任务，应保留可拆分视图。依据B02/B03。 |
| P05-N3 | P0 | 当前数据失效、计划过期、风险超额是明确的行动门槛。依据B05；是否允许人工覆盖及覆盖记录需另行验证。 |
| P05-N4 | P1 | 看盘→计划→模拟→复盘共用决策对象。依据B05/B07；现有工作流桥可复用。 |

**真实访谈证伪题：** 请受访者用最近一笔实际交易说明：触发后首个动作、会看哪些反证、哪一步会改选合约、哪些提示会主动关闭；再用当前产品的同一历史事件完成定位任务，观察真实犹豫点，不问“你是否喜欢统一工作台”这类诱导题。

## P06 十年经验的系统化CTA与量化研发者

人物设定是假设：能写代码或理解可视化规则，研究多个活跃品种，重视策略版本、样本外、交易成本和组合容量；不要求产品代替独立研究。这个角色没有被赋予虚构的管理规模或策略收益。

### 问题一：典型任务和限制是什么

**模拟回答：** 我从一个可证伪假设开始，确定数据群体、信号时点、成本、退出和对照，再跑实验。我的限制是容易试太多参数、实验难以追踪，以及看起来很好的单策略放进组合后失效。少一个指标通常不是主要瓶颈。

**追问：** 最先希望看到系统给什么？

**模拟回答：** 哪些实验已经做过、用了哪些日期和品种、失败在哪里、哪些结果只是重复历史探索。不要给我一个没有实验血缘的“最优策略”。

### 问题二：当前产品如何支持和阻碍

**模拟回答：** 工作流已有草稿、校验、发布和版本转回测/模拟，这个基础不能推翻。回测也能带URL版本号。问题是，我要把一个研究报告、版本、回测运行、空仓观察和模拟账本对上，仍分散在不同页面；用户得自己确认它们是否共享同一假设、样本和风险预算。

**追问：** 所以把它们放进一个长页面就解决了？

**模拟回答：** 不一定。应该是同一个实验对象和运行记录，多个工作视图。全部控件挤在一起反而让我难以比较版本。

**事实与假设：** B04/B07证明已经有重要桥接；B05/B06说明另一条研究计划/本机日志的对象体系不同。“所有血缘缺失”不能从这些文件断言；更准确的审查结论是当前可见界面没有统一展示跨体系的实验血缘。

### 问题三：面对预测冲突和弱证据

**模拟回答：** 先区分规则分数、历史条件概率、模型估计概率和已校准概率。一个75分和一条20%的稀有转折标签不能直接比较。每条输出应绑定目标、期限、基准、样本、标签可得时点、成本后结果及证据阶段。校准没做就写没做。

**追问：** 日线模型和线形模型方向相反怎么办？

**模拟回答：** 保留两个原始输出和共同适用样本，先知道预测目标是不是同一个。不能靠再加权生成一个更漂亮的总分。我也不接受文化参考无论权重多小都混入可交易概率或风险预算。

**事实与假设：** B05中 `calibratedWinRate:null` 是明确现状；B10指出某条融合路径仍混合文化参考。建议将文化内容留在独立资料/比较视图，是否保留为研究对象可配置，但不进入交易证据等级。

### 问题四：模块之间需要什么对象

**模拟回答：** 至少是 `hypothesisId → experimentId → runId → strategyVersionId → observationRunId → simulationSessionId`，并指向不可变的数据快照/哈希、品种群、训练验证时间划分、交易规则与成本版本。每次改参数生成新版本，不能更新同一个“最优收益”数字后找不到上一轮。

**追问：** 指标库在链条中处于什么位置？

**模拟回答：** 是可复用定义和输出规格，不是又一个列几十个指标的独立目的地。指标要有单位、输入周期、预热、缺值和形成中柱规则。缠论与普通指标都应通过同一节点/证据接口使用，但要保留各自确认延迟。

**待验证：** 这些是建议的对象模型。现有 `workflowVersion`、`shadow`、`session` 标识可做适配，并不表示必须推倒重建数据库或把所有概念硬改成一个ID。

### 问题五：哪些入口保留或合并

**模拟回答：** 我希望“研究”下面有假设/实验/版本/运行，工作流和回测是同一实验的编辑与结果视图；自主研究报告作为可关联证据库。实时观察与模拟是一条后续阶段，不能把历史回测收益直接当作可执行等级。学习和书籍可保留，但不占我的实验导航。组合层应明确区分“没有实现”与“实现了但隐藏”。

**边界：** B07展示的是模拟会话，B05计划有用户手填的其他风险，不足以证明已有完整多策略组合归因、相关性、容量、策略资金分配或企业级组合风险平台。这些若拟新增，应作为独立产品范围和数据建设，不靠改导航假装已具备。

### 问题六：可验收的理想流程

**模拟回答：** 一条失败假设也能完整走通：查看冻结协议，打开对应版本，重放同一运行，核对源指纹和成本，解释失败；进入纸面观察后只用未来新日期，最后把偏离项自动连回复盘。系统应允许“不发布、不交易”作为合法的完成状态。

**建议验收，非已测结果：** 挑选一个有实际数据与失败记录的既有实验，跨页面核对版本、数据范围和执行成本一致；保存新参数后生成新运行而不覆盖旧结果；模拟成交能回溯到对应信号与版本；未完成独立前向观察的版本不得显示“实盘验证通过”。

| 需求ID | 建议优先级 | 需求与可证伪假设 |
| --- | --- | --- |
| P06-N1 | P0 | 建立实验/策略版本/运行/观察/模拟的血缘视图，复用现有桥。若真实用户主要只做单个临时试算，应允许轻量模式。依据B04/B07。 |
| P06-N2 | P0 | 统一预测目标、周期、单位、证据等级和缺数语义；分数不冒充概率。依据B05/B10。 |
| P06-N3 | P0 | 保存失败与完整尝试历史，区分重复历史与新的前向样本。现有研究产物可复用，统一管理是提议。 |
| P06-N4 | P1 | 指标与缠论结构成为可组合能力，保留确认延迟和定义版本；不能只按技术名称堆模块。依据B04。 |
| P06-N5 | P2 | 组合风险/容量/资金分配先做独立需求验证，未具备时不以单策略图替代。依据B05/B07的能力边界。 |

**与其他角色的冲突：** 其版本与证据密度会压垮新手和盘中界面；他也可能接受较慢的离线实验，但日内用户不能接受。解决方向是共享对象、按任务渐进展开，而不是两套相互不通的简版和专业版。

**真实访谈证伪题：** 请受访者提供一次失败策略迭代，描述真正需要复现的最小材料；实际尝试从某个回测结果找回参数和源数据；比较他愿意采用的可视化编排和代码接口边界。不要用“你是否需要版本管理”替代真实任务。

## P07 七年经验的产业基本面与套保投资者

人物设定是假设：关注某条产业链的价格、库存、交割与期限风险，同时可能持有现货或经营敞口。该角色不被假设已经将企业数据接入本系统；套保资格、交割资格和企业审批流程均未调研。

### 问题一：典型任务和限制是什么

**模拟回答：** 我要知道一个事件影响哪段产业链、何时影响现金流，现货和期货的口径是否一致，再决定是否缩减风险或调整月份。我的约束不是猜中明天涨跌，而是采购/销售周期、现金需求、基差变化和可接受的保证金压力。

**追问：** 没有现货数据时，期货价量模型还有价值吗？

**模拟回答：** 有，但只能作为盘面状态。请明确“未取得现货/库存/地区品质数据”，不要把价增仓增直接叫供需验证，更不要把两个期货月份的价差写成已经确认的基差套利。

### 问题二：当前产品会怎样使用和卡住

**模拟回答：** 我会先看消息来源和发布时间，再进入品种。官方与媒体分开、显示条件和反证，是值得保留的。卡点在于：一条消息的“潜在传导品种”链接能打开行情，却没自动形成我的事件假设、经营敞口与对冲计划；之后还要重新解释我的持仓到底在保护什么。

**追问：** 是不是再加一个“产业”主菜单就能解决？

**模拟回答：** 如果底层仍没有现货敞口和数据定义，只会再造一个围栏。先让我在同一品种工作区看到已知、未知、来源、更新时间和计划用途。

**事实与假设：** B08确认已有来源与条件传导能力；B09确认部分“供需”输入是盘面代理。上述企业使用场景和审批要求是研究假设，不是产品已有业务。

### 问题三：冲突与弱证据时需要怎样解释

**模拟回答：** 期货上涨与库存下降是不是同一区域、同一品质、同一统计频率？近月和远月结构能支持怎样的情景，哪些库存数据缺失？我希望看到因果链上的证据与缺口，而不是让关键词情绪、价量指标和不确定的产业解释共同投票。

**追问：** “期限曲线贴水”可以直接提示做多吗？

**模拟回答：** 不可以。还要核对仓储、资金、交割、运输与可交割品质。对冲也不是为了赚这笔期货的钱，要看现货加期货的合并敞口。我愿意接受“只能描述盘面，无法证明套利”，不愿意接受长篇强确定性的说明。

**事实与假设：** B09中的说明强度与输入范围需要匹配；不据此断言实际所有品种都缺产业数据。建议按每个数据项来源与覆盖审计，不一概移除真实期限结构功能。

### 问题四：跨模块应携带什么

**模拟回答：** 事件ID与原始发布/采集时间、关联产业与品种、事实和解释的区分、现货口径（地区/品质/含税/单位/统计日）、实际期货月份和交割规格、经营敞口的方向/数量/期限、套保目标与风险限额，以及审批和复盘记录。如果目前无法获得某字段，就显示缺口，先支持人工录入并标明用户提供，不要默认为交易所数据。

**追问：** 哪些是首期必须自动化的？

**模拟回答：** 先把官方事件与品种、期限曲线、原合约计划串起来。企业现货台账、合并套保有效性和审批可以单列后续范围；第一期不要承诺已经自动计算我的企业总体风险。

**边界：** 当前 `ResearchPlan` 支持单合约风险试算和其他风险输入，不能据此称为企业套保管理。建议统一决策对象允许 `purpose=HEDGE`，但首期不支持的计算仍需明确禁用。

### 问题五：模块去留

**模拟回答：** 保留官方消息、期限结构、真实合约与交割规则，作为品种工作区的证据页签。产业事件不要和未经核实的解读混成“利多列表”。把供需压力改成与输入一致的“价量仓压力代理”，或等产业数据接入后再用供需名称。人物解读、书籍与文化参考可归档到资料区，不进入套保决策评分。模拟保留，但单策略收益图不能替代现货加期货的合并风险。

**与其他角色的冲突：** 他可能宁可错过盘中信号也要口径完整，日内投资者则重视速度；他需要月份/地区/品质差异，普通个人用户则希望减少字段。不能为了统一而把产业语义抹掉，也不应让所有人默认填企业字段。

### 问题六：可验收的理想流程

**模拟回答：** 从一个原始发布进入品种，建立可反驳的事件假设，明确我当前缺哪类数据；选择实际月份、填写需对冲的经营风险，再得到“可计算的期货风险部分”和“尚不能计算的现货/基差部分”。保存后跟踪事件和对冲计划，复盘时核对风险是否下降，而不是只问期货单腿是否赚钱。

**建议验收，非已测结果：** 选一条真实来源事件，原文、时间精度、品种关联和解释不得在导航中丢失；现货口径缺失时不能输出锁定套利结论；未提供现货敞口时只能做期货情景试算；合约换月时保留原月份及重新核算痕迹。若后续做套保模块，再定义经营敞口与合并风险的专属验收，不能拿模拟交易检查代替。

**真实访谈证伪题：** 请受访者用最近一次套保或事件应对，展示真实使用的现货口径、审批材料与现金约束；让其解释如何评估成功，确认他是否需要本产品承载台账，还是只需证据与月份研究。对“什么数据没拿到就绝不决策”逐项求证。

## 本组对重新设计的约束

1. **不要把“16入口改成5入口”当成完成联动。** P05要保留事件当时上下文，P06要保留版本和实验血缘，P07要保留证据口径；共享的是对象和身份，不是只共享一个品种字符串。
2. **已有联动应复用。** 当前预警到原合约、工作流版本到回测/模拟、部分策略委托回信号节点已经存在；新方案要把它们组成可检查的任务链，不应全盘否定。
3. **分数、概率、情景和行动门槛需分开。** 用户想要辅助决策，不代表允许把弱证据转成确定开仓建议；“等待、不采用、验证失败”必须是闭环的一部分。
4. **按任务渐进展开，避免再做互不兼容的简版/专业版。** 同一决策/实验/计划ID可以给日内、量化、产业三种视图，但时间尺度、资金风险和语义不能被统一分数吞掉。
5. **产品范围必须有诚实边界。** 实盘执行、完整多策略组合管理、企业现货台账与套保有效性在本组代码审查中没有足够依据宣称已实现。应列为待验证范围，而非重命名后宣布具备。

本组没有产生“3/3投资者都要求某功能”等实证结论。后续真实访谈应使用受访者自己的最近任务与现有产品操作，检验上述需求是否成立，并保留反例。
