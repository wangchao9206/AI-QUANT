# E02 量化投资与金融决策产品专家视角评审

日期：2026-11-07。身份与证据边界：这是一个**资深量化投资／金融决策产品专家的模拟分析视角**，不是聘请真人专家的背书。已完整阅读 P01—P10 模拟访谈、`code-audit.md` 和 `working-proposal.md`。模拟角色需求是设计假设，代码与冻结研究是可核对的现状；不得将十个人物的出现次数换算成需求占比，也不得将本评审称为真实专家共识。

## 一 独立判断

工作提案抓住了“任务闭环与共享上下文”的问题，但**导航收敛和统一计划不自动解决预测、策略与辅助的质量问题**。若只是把现有分数、历史频率和长篇解释搬到统一交易台，仍会让用户得到一个信息更集中的不确定答案。

产品应交付三层互不混淆的结果：

1. **对市场能提出什么可检验判断。** 明确目标、期限、数据截止时间、适用群体、基准与证据阶段。
2. **这个判断在当前交易方式下意味着什么。** 方向、速度、波动率、流动性、成本及风险预算，可能使“方向判断正确”仍不适合开仓。
3. **用户现在可以完成什么动作。** 观察、保存假设、补充数据、等待条件、修改计划、模拟验证或复盘；“不动作”须能完成任务，不能被设计成空白结果。

此定位响应 P01-N2、P05-N2、P06-N2、P08-N2、P09-N2、P10-N2。它**不承诺改版提高样本外alpha、胜率或用户收益**；这些必须通过冻结协议后的新样本单独检验。

## 二 对“预测”建立五种输出契约

不能再用一个 `confidence` 或“看多”字段承担以下五类含义。各类均使用共同的合约、时间与版本头，但保持独立业务类型。

| 输出类型 | 回答的问题 | 必须字段／约束 | 页面应如何称呼 |
| --- | --- | --- | --- |
| 模型分数 `ModelScore` | 输入按当前规则打分后偏向哪一侧 | 分数范围、输入覆盖、定义版本、哪些缺值未参与；相关输入不得被描述为独立投票 | “方向参考分／排序分”，不得加 `%胜率` |
| 规则事件 `RuleEvent` | 当时明确的条件是否满足 | 规则与参数版本、前后状态、指标单位、完整柱/盘中触及、触发与首次可知时间、原始依据 | “已触发／未触发／待确认”，不隐含盈利概率 |
| 历史条件统计 `ConditionalEvidence` | 某类历史截面符合条件后，指定未来标签出现频率如何 | 标签、样本群、训练/验证/近期范围、匹配基准、样本量与重叠限制、费用后独立观察结果、搜索与复用声明 | “历史标签频率”，不是当前个案的已校准概率 |
| 预测分布 `ForecastDistribution` | 在该合约、截止时点和期限下，未来目标的概率或区间是多少 | 目标集合与是否互斥、期限、预测产生/可得时间、有效期、版本、已冻结校准与前向验证记录、基准及失效/漂移状态 | 只有满足预测契约才称“预测概率”；未校准可保留“研究估计”身份，不伪装完成校准 |
| 条件计划 `DecisionPlan` | 在账户、持仓、报价、预算与失效条件下，允许准备哪一步 | 计划版本、所有者、标的与执行合约、方向/各腿、预算、触发/失效/到期、数据与证据快照、行动门槛及覆盖记录 | “观察／待核对／等待触发／可送模拟”等行动状态；不能由预测字段直接生成已执行 |

现状依据：`code-audit` F04/F08/F09/F11，访谈 B05/B10、C-E03/C-E04。目前的 `calibratedWinRate:null` 与 `tradeQualified:false` 必须在新契约中继续如实表达。不能为使页面“更像预测”而填一个百分比。

### 一张合格的预测／观察卡

卡片首层只需回答：**预测什么、多久、基于何时、在哪些品种适用、支持与反证、当前该做什么**；完整研究在第二层展开。建议结构：

- 标题：“未来8根15分钟柱出现何种价格路径”，而不是无期限的“看多”。
- 证据身份：“规则触发／历史条件统计／研究估计／冻结前向评估”，避免亮色百分数先于身份。
- 数据与期限：实际合约、源时点、信号时点、首次可知时点、失效时点、回放或当前观察模式。
- 相对基准：若只知道条件频率，显示该条件与相同范围基准；若有预测概率，展示校准适用范围与最近评估。
- 支持与反证：最多先展开两个支持、一个实质反证；不是用更多解释文字制造证据数量。
- 费用与行动：若独立观察交易的成本压力结果为负，应与概率改善同时呈现；仍可保存观察，但不能自动升级为可执行计划。

P01需要可解释摘要，P04/P06需要图上与版本证据，P05需要快速定位，P08需要预测与期权表达分离。首层简洁不应删除重要限定，深层专业也不应要求所有用户阅读全部研究表格。

## 三 目标 周期 冲突与失败的处理

### 目标必须可检验

“趋势上行”“局部向上拐点”“先触及2ATR再触及止损”“持有期净盈利”是不同标签。必须定义价格/回报的单位、评估起点、观察窗口、同柱路径歧义、停牌/休市和退出规则。上涨、下跌、拐点、入场窗口不默认互斥，**不能为了画三块概率图而强迫它们相加等于100%**。

预测目标的完成时间应单独记录。未来标签未到期前只累计待评价记录，不能把未结局记录塞进胜率分母，不能在回放中提前读到最终修订的缠论结构。P04-N2、P06-N2/P06-N3是这一契约的直接需求来源。

### 冲突保留 不能先平均

工作台按目标与期限对齐再比较。日线背景偏多、15分钟下破、期权IV偏高并不必然是模型互相打架；它们可能回答不同问题。相同目标的冲突，应并列源输出、适用范围、缺数据和最近漂移，不用多数票或加权分覆盖反证。高度相关的均线、通道和MACD也不能被呈现为三个独立专家。

行动优先顺序建议为：**权限/数据/合约有效性 → 原计划失效与持仓风险 → 触发条件与执行条件 → 新的研究判断**。原计划已失效时，不因另一个模型分数偏多而静默续命；需要新计划版本与人工理由。对应 P05-N3、P09-N1/P09-N2、P10-N2。

### 缺数与失败是产品状态

`WARMING`、`STALE`、`OUT_OF_SCOPE`、`INVALID`、规则未触发、计划过期、模型漂移不能合并成一个灰色“暂无机会”。每个状态应说明其作用范围、最后成功时点、恢复条件和允许动作。例如：报价过时仍可阅读冻结报告；只允许保存准备方案，不能按旧报价生成新模拟执行意图。

失败复盘至少区分：数据/时间错误、定义或规则错误、信号未达预期、成本侵蚀、执行偏离、预算/纪律偏离。单笔盈利也可能违反规则，单笔亏损也未必能否定策略。对应 P03-N2、P06-N3、P09-N4。

## 四 策略与指标如何达到预期

### 指标是有规格的组件 不是功能墙

每个指标/结构组件建议登记：`indicatorId`、定义版本、输入类型与周期、单位、预热长度、形成中柱政策、缺值政策、首次可知延迟、修订政策、计算来源、与其他组件的依赖。缠论的笔/中枢和普通MA都能通过组件接口被规则引用，但不能抹掉结构确认延迟。手画线仍是个人假设；只有冻结锚点与可执行判定规则后，才成为可回测的研究定义。

页面按“趋势／位置／动量／量能／波动／结构”组织工具用途，默认只展示当前方案引用的组件，允许专业用户直达完整定义与图层。推荐指标不是按名称堆叠，而是明确它为当前假设提供了哪种新增信息。对应 P04-N1/P04-N3、P05-N2、P06-N4。

### 策略必须是完整决策政策

一个策略版本至少包含：适用品种与市场状态、信号定义、数据周期、入场时点与委托假设、退出/失效、风险与数量规则、成本、换月/交割、禁止交易条件、验证协议。只有入场指标组合而没有退出、风险和执行假设，称为“信号规则”，不称完整策略。

策略模板应解释为什么可作起点、何时可能失效、哪些参数不是已验证最优值。用户复制模板后形成自己的草稿；修改参数生成新定义版本，不得把旧研究与新参数继续混作同一成绩。保留现有工作流草稿/发布版本、节点试算与回测/模拟桥（F05、B04），不用新页面再造一套策略引擎。

### 资格不是一条“是否盈利”的开关

建议三条独立资格轴，避免“没验证盈利就不能模拟”阻断研究，也避免“能运行就能交易”：

| 资格轴 | 可以证明什么 | 不证明什么 |
| --- | --- | --- |
| 计算/运行资格 | 输入、单位、时间界限、确定性、接口与状态校验正确 | 不证明样本外有效或赚钱 |
| 统计证据阶段 | 历史审计、冻结验证、前向观察的范围和结果 | 不自动证明当前个案可执行，不保证未来alpha |
| 执行/风险资格 | 当前权限、合约、报价、预算、成本与计划状态允许某一步 | 不把弱研究证据变强，也不代表实际成交 |

对应阶段与门槛建议：

| 阶段 | 不可缺门槛 | 可开放动作 |
| --- | --- | --- |
| 模板/假设草稿 | 目标、组件、假设和未定义部分清楚标识 | 编辑、保存、查看；不生成伪信号 |
| 可重复规则版本 | 单位/预热/缺数/完整柱/修订规则测试；确定性定义与版本冻结 | 节点试算、历史研究；明示研究身份 |
| 历史回测运行 | 冻结数据范围、实际合约/换月、进出场与费用、对照、全部尝试记录；未来标签边界可查 | 查看与比较结果；不能标“前向验证通过” |
| 冻结验证 | 在读取后段结果前固定候选与评价协议，处理标签重叠和边界；改阈值即新一轮 | 描述适用证据；不能反复看后段仍称全新留出 |
| Shadow前向观察 | 先保存预测/信号、模型与规则版本及可得时间；未来目标到期后再评价；新模型不改旧记录 | 非执行观察与研究预警，追踪遗漏/重复/延迟及漂移 |
| 申请预警 | 计算资格、适用范围、订阅与去重权限通过；明确研究级还是运营可用级 | 可发“条件观察”提醒；弱证据不能改名高胜率 |
| 申请模拟 | 计划完整、风险/合约/时点/费用/权限通过；研究与训练账本明确分开 | 未验证策略也可进隔离研究模拟，但不得升格为盈利验证 |
| 实盘执行 | 本次范围之外，需独立券商接入、授权、撮合/部分成交、撤单/断线、保证金与合规验收 | 不因此次改版新增真实下单 |

不能用同一个 `tradeQualified` 布尔值代替全部资格。旧字段可保留兼容，新增结构化 `eligibility` 与具体门槛结果；老研究 `false` 不得因迁移自动改为 `true`。对应 P06-N1/P06-N3、P08-N3、P09-N3、P10-N1。

## 五 未来预测能力的建设与评价

根方案提出“经过新数据校准的预测概率”是正确方向，但首期应把它当作独立研发流，不作改版必达的准确率承诺。

1. 先定义有限目标与期限，而不是一次预测所有品种、周期和交易方式；留一条可信基准，如同范围历史发生率及简单可复现模型。
2. 保存生成时间早于未来结果的预测账本，记录模型、输入指纹、预测分布、适用范围和数据质量，形成不可回填的评价集。
3. 同目标报告概率质量、校准、覆盖、样本与不确定性：可采用Brier/对数损失、可靠性图、分组校准及区间覆盖等候选指标。指标选择与最低可解释样本须在协议中先定；不在本评审虚构“应达到多少分”。
4. 将预测质量与交易政策收益分开评估。交易评价另包含费用/滑点、成交可达性、换月、信号重叠、资金约束与组合关联，不把独立事件均值标成账户收益。
5. 按时间和品种记录漂移及适用范围变化。基准或数据异常时降级为观察、暂停新计划的相关依据，并保留已有计划的处理路径；不靠重新训练后覆盖旧预测消除失败。

现有研究已重复使用部分历史，F08明确这一边界。即便改用另一个模型或重新命名分区，也不能把这些历史当作研究者从未见过的新证据。P06-N3、P08-N2、P10-N2要求的是可追踪证据，不是用更多小数包装信心。

## 六 决策助手不应只是另一个聊天框

助手围绕当前对象执行受约束的任务，而非从上下文丢失的聊天中重新猜品种：

| 助手任务 | 输入与输出 | 防止的错误 |
| --- | --- | --- |
| 解释与找反证 | 引用当前证据快照，输出支持、冲突、缺口与适用期限 | 不凭空补充没有来源的库存/新闻/胜率 |
| 比较表达 | 同一假设、预算、时点下，比较期货、期权单腿/组合和不交易情景 | 不按最高盈利倍数或最低权利金排序 |
| 形成计划草稿 | 输出拟变更字段、所用来源、版本与失效条件预览 | 不把一段自然语言解释直接当可执行规则 |
| 核对风险 | 调用确定性的风险服务，列覆盖与缺失 | 不由语言模型心算手数、保证金或最大损失 |
| 复盘归因 | 关联原计划、原证据、实际模拟委托/成交与新事实 | 不用今天的模型重新解释成当时已知 |

变更计划、订阅或模拟运行时，需要有明确的目标对象和变更预览。可按既有授权提供批量/低摩擦工作流，不必每次查看都弹确认；但不能因为“专家模式”而绕过后端权限、版本冲突或风险门槛。对应 P01-N3、P05-N4、P09-N1、P10-N3/P10-N4。

## 七 期货与期权的金融边界

### 期货

分开主连研究身份与实际交割合约执行身份；换月是需留痕的映射与再核算，不是静默换字符串。单笔“按止损价测算风险”不是保证封顶的最大亏损，跳空、封板、流动性和保证金压力应有压力情景。没有完整持仓覆盖时，显示“仅覆盖这些模拟/手工记录”，不可画成全账户组合风险。对应 P05-N3、P07-N3、P09-N1、P10-N2。

### 期权

同一标的方向判断必须先经过“交易表达”层：期限、IV、时间价值、各腿价差、手数比例、费用和退出时点都会改变损益。标的下跌标签概率不等于认沽赚钱概率，168个快照结构情景也不是期权历史盈利回测（F11、P02-N1/P02-N2、P08-N1/P08-N2）。

多腿对象至少保存有序 `legs[]`、真实代码/到期/方向/比例/乘数、各腿bid/ask及挂单时点、模型/利率假设、净成本、计划持有期、IV/标的压力情景与预算。任何一腿过时、缺乘数、移除或比例改变，原“限损组合”资格需失效并重算。到期数学最大损失、持有期浮亏、保证金、分腿成交和提前行权必须分别展示；没有经纪商规则就写保证金未知。

建议P0先提供多腿**研究草稿与风险比较**契约；期权历史回测、组合撮合、行权/指派、保证金与交割处理应独立立项。不能为了五入口看起来完整，提前画“期权模拟已执行”按钮。专业链表仍可直达，不强迫P08只能看简化推荐卡。

### 非实证内容

建议文化/人物/阅读内容保留独立资料、学习或用户自选对照，但默认不进入概率、行动优先级、风险预算或仓位。理由是证据身份不同，而不是贬低用户偏好。F09表明当前存在不同口径，需要按具体路径审计和迁移，不可一句“此前已隔离”带过。这个建议应在最终方案中列为产品裁决，当前并未改动算法。

| 五主入口被当作产品完成标准 | 反对。任务闭环与输出契约先于菜单数；首期验收必须穿越已有真实对象和版本，而不是只证明五页能点开。 | E01决定默认起点与信息层级；E03决定迁移成本。 |

| 所有研究都先发布策略，才能形成计划或模拟 | 反对作为统一强门槛。手工计划可有自己的冻结版本；未验证规则可在隔离研究模拟中试验，明确其身份。否则主观交易者被迫走量化发布流程。 | E01协调P04/P05/P09的摩擦与P06的复现需求。 |
| 用一个证据等级顺序决定全部功能开放 | 反对单轴。计算正确、统计证据、执行条件是三条轴；研究级预警可用但不代表alpha，良好统计也可能被当前流动性或预算拒绝。 | E03落实可审计门槛结果；E01保持可理解标签。 |
| 机会池合并后按一个综合分统一排序 | 反对默认跨目标排名。先按持仓风险、期限、关注范围和可操作状态分层；同目标内可解释排序，保留规则身份与相关性。 | E01界面复杂度和筛选默认值。 |
| 把“预测提升”列为一期必达收益 | 反对。第一期交付可检验目标、不可变预测账本和基准协议；模型进步需新数据证明，不能排期保证。 | 产品负责人决定研发投入和停止条件。 |

## 十 最终给产品负责人的建议

首期的“达到预期”应具体化为：用户能够对同一想法看见明确的市场判断、反证和证据边界，比较交易表达，形成风险预算内且会失效的计划，并在后续看到原判断、模拟执行和偏离原因。它不是少几个菜单，也不是增加一排模型。

预测研发与流程重构可以并行，但发布评价要分开：流程用真实任务的合约/时间/版本理解、风险解释、错误恢复与可追溯验收；预测用冻结后的新样本、基准和校准/交易协议评价。没有真实用户基线时，不报告任务成功率改善；没有新的前向样本时，不报告预测或收益提升。
