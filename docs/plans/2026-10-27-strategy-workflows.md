# 可执行策略工作流实施计划与架构决定

**Goal:** 让策略像 n8n 一样可拖拽节点、连线、配置参数、保存/发布，并真实用于逐节点试算、历史回测及历史/实时模拟交易。

用户已确认需要「可拖拽编排并实际运行」，不是只展示流程图。保留现有策略、书籍、账户及全部未提交修改。

## 架构决定 ADR-WORKFLOW-001

采用受约束的有向无环图 DSL：行情、价格、指标、常量、运算、比较、逻辑、持仓、内置策略、风控、交易动作。明确端口类型，禁止循环、未来偏移、缺失输入、无效类型及任意脚本。单一行情源表示调用方在决策时点已知的已完成日线；单一风控节点配置固定手数和 ATR 保护。

图形不是单独一套前端模拟：Python 执行器与原有日线信号共用现有策略规则；公开工作流 API 由既有 paper 网关转发，Java 只管理持久化、发布版本和账本。已有 strategy-service 的预测/研究功能保持独立，避免另建执行账本。对比方案是仅展示预设流程图（不满足用户要求）、引入通用脚本/外部编排平台（执行权限、可重现性和运维成本不合适）。

草稿可不完整，保存采用乐观锁。发布时通过 Python 图校验，生成不可修改的版本；回测通过 Java 版本接口注入服务端定义，模拟账户冻结版本与定义，后续编辑不影响既有试验。节点日志记录真实计算结果和候选动作，不把信号试算称为成交。

## 实施步骤

1. **执行器与图校验**：新增 `backtesting/workflow.py`，定义节点/端口/参数、拓扑校验和因果指标；内置六种策略作为可拆接的策略节点；新增 Python 回归覆盖连线类型、循环、冲突信号、预热、未来数据和因果性。扩展 paper 信号输入为 WORKFLOW + 冻结图，返回节点轨迹；新增内部校验和只算信号的调试接口。
2. **持久化与版本**：新增 V6，保存工作流草稿、不可变发布版本、会话版本/图快照及节点轨迹。新增 Java 工作流 API：列表/草稿读取、带修订号保存、幂等创建/发布、版本读取、节点试算、版本回测。上游计算放在数据库事务之外。
3. **真实执行衔接**：WORKFLOW 模拟账户只接受已发布版本，风控参数来自该版本；Python 信号与 Java 实际订单/去重/移仓/费用继续使用原账本。回测复用实际合约撮合，按图的固定手数和 ATR 规则执行，已有策略行为不变。
4. **可视化编辑器**：新增工作流页面、模板、SVG 节点画布、拖拽/缩放/平移、端口连线和删除、节点参数面板、撤销重做、校验提示、逐节点试算日志、草稿保存及版本发布。策略入口接入工作流；桌面与手机支持点击添加和连线。
5. **回测/模拟界面**：支持选择已发布版本，展示冻结规则与版本号；编辑器可将版本送去回测或模拟创建表单。节点轨迹可在模拟决策记录查看。原手动/预设策略与个人训练继续可用。
6. **验证与部署**：执行 Python/前端/Java 回归、隔离数据库和真实 HTTP 端到端测试、真实浏览器拖拽连线/保存/发布/试算及手机验证。构建更新算法、模拟服务与前端，检查 V6 迁移及业务状态前后一致；测试写入只发生在隔离环境。

## 可复现与失败边界

- 冻结定义、发布版本、引擎版本和风险配置；旧会话不自动升级。
- 历史信号严格截止游标，下一根可执行日线成交；实时只处理已完成日线和有效报价。
- 不支持逐笔或任意脚本节点；同根多空候选冲突时等待，缺数据时预热，不补造信号。
- 图形编辑/节点试算不产生订单，只有明确创建的回测或模拟试验调用执行账本。
- 无数据、无发布版本或图无效时说明原因；不给演示数据伪装成真实试算。

## 完成结果

已完成步骤 1–6，并部署到本地现有服务。草稿、发布版本、节点执行器、编辑画布、历史回测、历史/实时模拟及节点决策轨迹已打通。完成执行器/前端/Java 回归、隔离真实 HTTP 和浏览器端到端验收，并以真实焦煤日线进行无写入试算。原有账户和书籍记录前后核对一致，所有测试业务写入位于临时无卷数据库。完整执行范围与证据见 docs/operations.md 和 docs/verification.md 的工作流段落。
