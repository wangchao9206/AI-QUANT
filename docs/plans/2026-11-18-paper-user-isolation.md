# 模拟数据按用户隔离修复

**Problem:** admin与test同属默认工作空间，现有模拟账户只按tenant隔离，导致同租户其他用户能读取和操作账户。审计确认当前五个账户均由admin创建。

**Plan:**
1. 先备份，再增加paper_session.owner_id及个人版本/复盘的owner_id。优先按成功创建请求的用户审计回填，仅有唯一归属证据时分配；不确定记录保持隔离，不默认交给其他租户成员。
2. 原tenant RLS之上增加用户所有权限制。持仓、委托、成交、心得、行情档案、策略运行、训练和复盘均继承父账户可见性；策略运行日志也检查父运行。管理员角色不绕过私人账户隔离。
3. 通用已验证身份事务设置app.user_id，确保普通训练接口和后台任务使用一致的签名身份。默认个人策略版本按用户生成独立ID。
4. 历史资金、流水、ID不变。先在生产数据库事务性应用可重入隔离策略以关闭泄露，再部署对应Flyway迁移和完整代码。刷新连接池避免旧结果类型缓存。
5. 同租户两名用户分别建账户，互相测试列表/详情/行情/流水/心得/下单/撤单/删改/自动执行越权，并覆盖同浏览器切换登录。验证admin仍有原五个账户，test只能看到自己创建的数据。
