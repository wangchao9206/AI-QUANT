# 缠论研究到模拟工作流：实施边界

2026-10-31。现有链路审查后的下一阶段设计，尚未实现，不代表已放行交易。先支持冻结日线历史模拟；实际开市前向与日线可得性验收之前，不把分钟雷达候选直接推入现有日线账户。

## 现有可复用路径

- `backtesting/workflow.py` 编译有界图，现行DSL为1、引擎为`workflow-daily-v1`；输出buy/sell/close布尔端口。
- `StrategyWorkflowService`、`StrategyWorkflowStore` 保存草稿和不可变发布版本；模拟会话保存完整workflow_snapshot。
- `algorithm_service/paper_strategy.py` 接受当前观察时点和已知行情；节点trace持久化于`paper_strategy_decision`，模拟订单复用现有时点幂等和账户撮合。
- 历史回测与Java模拟账本成交模型不同，不能以共用信号推断逐笔成交一致。自研日线成本实验已独立验证，但目前没有工作流节点或订单桥接。

## CHAN_SIGNAL 的确定性合同

新增DSL2及`workflow-daily-v2`，旧DSL1继续由原版本执行。仅新版本允许CHAN_SIGNAL；发布、试算、回测和模拟响应分别核对定义所要求的引擎版本，拒绝默认升级旧版本。

节点参数白名单至少包括：自研引擎/具名规则版本、计算与资格代码摘要、输入价格口径、候选类别过滤、首次观察资格和退出规则。摘要在新建节点时从服务器取得，已有版本保留其摘要；源码/规则漂移时拒绝执行，不自动替换。

候选只在首次可观察根生成入场条件，不能使用最终仍存活的候选列表过滤历史。持仓方向、冲突、失效退出、末根无法成交都分别记录；信号资格与原始engineConfirmed/eligibleAt分开。失效退出必须明确是“同方向任一候选失效”还是“实际入场候选失效”，不能在只传持仓方向的旧接口中冒充后者。需要入场对象语义时扩展执行上下文。

预计算必须保存每个观察时点的独立不可变快照，不能让NativeEngine后续失效更新污染早期trace。每条trace带输入起点/根数/摘要、观察索引、规则/资格摘要、候选与失效证据、端口值和拦截原因。窗口起点变化需要显式识别，不能把滚动5000根窗口当同一原点的持续内核。

## 影子观察与发布

在已发布配置之上增加持久影子观察：精确版本、品种、观察界限、假设持仓、输入/规则摘要、节点trace、实际保存时间，以及“仅计算不下单”的范围。UUID命令幂等、变更冲突、冻结恢复不重新取行情。历史影子试算与实际开市前向分开标记，不能混称。

创建缠论模拟会话前核对对应版本的影子记录，并把引用冻入workflow_snapshot；不修改用户已有账户或切换其策略。新账户与启动动作由明确的产品按钮触发；验收只能使用隔离临时数据库/账户，不对用户现有账户生成订单。

工作台/策略实验增加“创建缠论工作流草稿”的入口；工作流编辑页展示资格、原文与影子档案；模拟决策可展开完整证据，最终订单可回到冻结图表及该节点，不留下仅有文字原因的孤立订单。

## 必须通过的验证

1. 改变未来OHLCV不改变过去端口与trace；后续失效仍保留首次入场候选。
2. 相同前缀批量准备与逐根准备一致；不同窗口起点不静默续接。
3. 多空同时、无合约ATR、末根、费用/保证金/成交量不足都保留拒绝原因。
4. DSL1所有既有信号与账本回归不变；DSL1拒绝CHAN_SIGNAL，错误规则摘要拒绝执行。
5. 影子UUID重试/冲突/恢复、跨版本/跨品种引用拒绝、真实时点与历史重建语义分离。
6. 隔离Java/PostgreSQL与真实信号服务演练订单时点、单次幂等、冻结输入、规则与影子引用；不对用户已有账户下单。
