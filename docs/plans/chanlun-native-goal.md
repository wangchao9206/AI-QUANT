# 自研缠论中心目标与验收

2026-10-31，用户明确要求不等待 chanlun-pro 授权，自己实现同类能力，并以“比 chanlun-pro 好”为建设目标。原设计中可选 pro 授权 Worker 的路线取消；该项目仅作为公开功能与交互流程的参考。

## 当前交付：自主计算内核 v1

`chanlun_worker/native.py` 使用 Python 标准库独立实现，不调用 chanlun-pro、chan.py、CZSC 或旧研究基线的计算代码。版本为 `aiquant-chan-v1`，接入独立 Worker，工作台默认使用它。旧研究基线保持原名字与行为，公开引擎继续用于对照。

已实现包含处理、封存合并 K 线上的分型、可变化末笔与已封存笔、特征序列线段（含缺口后等待反向分型）、动态线段、笔中枢及延伸/离开、B1/S1/B2/S2/B3/S3 研究候选、候选失效跟踪。每个对象带规则、构成位置、首次观察与修订证据，规则关联的参考课可在系统内打开。

## v1 明确口径

- 开头没有已知方向时，包含处理采用固定向上初始方向；遇非包含 K 线后按实际方向处理。这是具名启动约定，不能声称覆盖所有初始条件下的唯一划分。
- 三根合并 K 线的右侧 K 线封存后才确认分型。两分型中心至少相隔四根合并 K 线；当前末笔可变化，后继相反笔成立后封存。
- 线段输入为已封存笔。特征序列按段方向处理包含；无缺口时按特征分型结束，有缺口时继续等待反向特征分型。递归层级和其他包含口径尚待扩展与专项核验。
- 当前中枢来自三根已封存笔，固定初始重叠核心，延伸时不悄悄改变边界。不能等同于所有引擎的线段中枢。
- 一类候选需要两个同向且不重叠的中枢背景、同向笔创新高低及 MACD 同号面积衰减到前段的 90% 以下。这是动力辅助的研究操作条件，不把它当成原文充分条件的证明。
- 二类候选要求已出现且未失效的一类候选、一次反弹/回撤以及不破原点。三类候选要求离开后的回踩笔严格位于中枢外，观察到确认前若已经触及边界就拒绝生成。
- 候选生成后，后续触及失效价会记录为失效；不删除先前观察，不回填订单。全部 `eligibleAt=null`，尚未赋予交易资格。

## 怎么判断“更好”

目标以用户可完成的任务和可复现实验验收，不能只靠功能数量或主观截图。

| 维度 | 放行证据 | 当前状态 |
|---|---|---|
| 自主可用 | 无 pro 组件/密钥；独立镜像能运行 | 内核与适配已实现 |
| 结构可信 | 包含、分型间距、缺口线段、严格回踩、延迟确认、失效反例；前缀重建一致 | v1 单元与回归通过，继续扩充反例 |
| 因果与审计 | 任一信号回到当时可得数据、源码与参数版本、修订链 | 日期级审计已接入；精确可得时间待完善 |
| 原文联动 | 结构规则与对应原文在同系统查阅，说明解释口径 | 已接入规则参考课；非唯一标准标注 |
| 回放训练 | 服务端推进、先提交判断、无未来载荷 | 独立训练页与服务器状态机已实现，前缀/并发/恢复/末端实际接口验收通过 |
| 研究与执行 | 真实合约、费用、滑点、保证金、换月、失败订单可追溯 | 已接入研究账本，五情景与逐笔对账；逐日费率和前向观察仍待完善 |
| 雷达与运维 | 离开页面仍监控，重启恢复、断流暂停、事件去重 | 真实交割合约日/5/30 分钟接入，隔离故障演练通过；实际开市增量与前向稳定性待观察 |
| 性能体验 | 固定输入/硬件的计算与交互测试，公开样本量和限制 | 已提供可复现计算基准脚本，浏览器控制关闭期间不声称完成视觉验收 |

未经合法运行对方核心与相同条件对照，不能证明数值准确率或速度超过对方。先证明本系统自身正确、可用、透明，再针对公开工作流逐项评审改进。收益优势需要冻结规则后的真实成本验证与前向观察。

## 第一轮计算基准

固定 1,894 根 FU 日线，在本机 Windows AMD64 / Python 3.11.9 上运行五次：增量内核中位约 0.016 秒，包含逐根结构观察与全部修订审计的计算中位约 0.93 秒（最大约 2.14 秒）。这是单机实测，未包含 HTTP、数据库或浏览器，也没有测量 chanlun-pro。

优化仅缓存不可变封存对象与结构身份。优化前后全历史结构和修订（剔除实际写入时间）摘要保持 `407456aac0e762ab0db073d33d13ce4bd7defa0b0a8a2861b681204b4cf46c92`，对象计数与事件数均一致。测量记录见 `docs/research/data/chanlun-native-2026-10-31/benchmark.json`；优化前单机记录另存，不能视为控制了所有系统负载的性能比较实验。
