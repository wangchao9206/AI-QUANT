# 策略启动数据刷新 Implementation Plan

**Goal:** 每次点击启动，以及服务重启后恢复已有策略时，先从天勤重新拉取实际合约日线和分钟线，验证并显示更新结果后再允许开仓。

**Architecture:** 行情服务增加有界、单工作线程的刷新队列，工作线程独立拥有短生命周期TqApi，不在HTTP线程操作原实时SDK。每个“运行ID＋本次服务启动标识”独立申请刷新；轮询同一申请幂等，失败按退避重试。真正重新连接并下载日线/分钟线，校验实际合约、时间、OHLC和序列覆盖，再原子保存带来源的历史文件并更新实时快照。原行情订阅继续运行，冻结的历史回放档案不变。

**Steps:**
1. `data/automation_refresh.py`及内部API：异步真实下载、幂等队列、校验、原子保存；不把接收时间当成报价时间。
2. `PaperAutomationService`及客户端：启动数据门槛；未更新时不计算新开仓，已有持仓的保护仍可使用有效实时报价。更新回执保存在现有决策日志，无数据库结构迁移。
3. 页面增加“正在拉取最新数据”状态、最新日线/分钟时间、条数和更新时间；每次重新启动显示独立结果。
4. 测试重新启动必拉、轮询不重复、更新失败不开仓、缓存旧数据不能冒充新下载、休市仍可更新历史；部署原Docker，隔离QA验证两次启动不同刷新申请和持久化回执。
