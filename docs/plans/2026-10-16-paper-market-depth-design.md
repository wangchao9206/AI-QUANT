# 模拟交易删除、五档盘口与逐笔成交设计

## 边界

- 删除对象是完整模拟试验，会级联删除该会话的行情路径、合约规格、换月事件、委托、持仓和成交；前端必须二次确认。
- 五档盘口和逐笔成交只用于 `LIVE` 模式，数据源固定为已认证的 TqSdk 会话。历史模式不生成或推测盘口。
- 上游没有返回的档位保持空值。逐笔方向仅依据成交价与当时买一/卖一推断，无法判断时返回 `NEUTRAL`。

## 数据流

`Vue 交易台 → Gateway → Market Service → Python/TqSdk`。Python 复用唯一 TqSdk 会话，只在首次请求某个实时合约的微观行情时建立 Tick 序列订阅。Quote 对象提供五档价格和数量，Tick 累计成交量的相邻差值形成逐笔成交量。内存快照由接口读取，不在 HTTP 请求线程中访问上游。

页面每秒轮询当前实时合约；请求完成后再安排下一次，避免慢请求重叠。切换会话或离开页面立即停止轮询。数据响应包含合约、数据源、数据状态和交易所时间，界面始终显示新鲜度。

## 稳定性

- 微观行情按合约惰性订阅，限制每个 Tick 序列为最近 200 条。
- 所有 NaN/无效价格在 Python 边界转换为 `null`，禁止向 JSON 泄漏非标准数值。
- 删除使用数据库级 `ON DELETE CASCADE` 和单条主记录删除，保持原子性。
- 实时接口不可用时保留最后一次成功显示并标记错误，不替换为演示数据。

## 验收

- 删除一个试验后，列表和所有子表均不再存在该会话记录。
- TqSdk 已连接时，实时会话返回五档结构、交易所时间和最近真实成交。
- 相同会话连续刷新不产生重叠请求；历史会话明确提示不提供历史盘口。
- Python、Java、Vue 测试及 Docker 生产构建全部通过。
