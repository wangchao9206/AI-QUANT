# 模拟交易与历史回放系统设计

## 目标与边界

系统提供两个严格隔离的纸面交易模式：`LIVE` 使用真实最新行情，`HISTORICAL` 使用创建会话时冻结的真实历史主力合约数据。两种模式共用订单、撮合、保证金、持仓和资金账本，不连接真实交易柜台，不允许把模拟订单误发为实盘委托。

首版支持独立模拟会话、市价单、限价单、止损单、撤单、逐根 K 线推进、可调速自动回放、当前持仓、委托、成交、权益和已实现/未实现盈亏。历史模式只能使用当前已公开 K 线生成订单，并在下一根 K 线上撮合，防止未来数据泄漏。主连切换必须使用天勤真实交割月映射和新旧合约价格；缺少任一腿时暂停而不是补造价格。

## 方案比较

1. 仅在 Vue 浏览器内模拟：实现快，但刷新即丢失、可篡改、无法并发控制，否决。
2. 全部放入 Python 算法服务：复用行情容易，但把资金交易状态混入算法进程，不符合 Java 业务微服务 + Python 算法服务边界，否决。
3. 独立 `paper-trading-service`：Java 管理 ACID 业务状态，Python 提供真实数据，PostgreSQL 持久化；运维略有增加，但边界清晰、可审计且能横向扩容，采用。

## 架构

```text
Vue 模拟交易台
      │
Spring Cloud Gateway
      │
paper-trading-service ── PostgreSQL / paper_trading schema
      │
      ├── market-service（实时行情）
      └── algorithm-service（真实历史主力映射、合约规格、换月双腿）
```

`paper-trading-service` 是订单与资金的唯一写入者。外部行情调用在数据库事务外完成，随后通过会话行锁和版本号在短事务中撮合。客户端为每个创建、下单、撤单和推进操作提交幂等键；服务端唯一约束保证重复请求不会重复成交。

## 撮合规则

- 历史市价单：下一根 K 线开盘价加不利方向的最小价位滑点。
- 限价买单：下一根最低价触及限价后成交，成交价不高于限价；卖单对称。
- 止损单：下一根高低价触发后转为市价单，跳空时按开盘价与触发价中更不利者成交。
- 单根 K 线最大成交量受该 K 线成交量比例限制，超出部分保留为部分成交。
- 保证金和手续费取上游合约规格与用户保守参数中较高值；只允许整数手。
- 平仓优先于反向开仓；禁止负可用资金和超过持仓的平仓单。

## 可靠性与安全

- PostgreSQL 外部 ID 使用 UUID，内部事件使用 identity；所有外键建索引。
- 会话写操作固定按会话→订单→持仓顺序加锁，事务中不执行 HTTP 调用。
- 请求字段使用 Bean Validation；价格、手数、日期范围和字符串长度都有上限。
- 网关仅暴露 `/api/v1/paper/**`，服务没有实盘柜台依赖和密钥。
- 每次成交保存行情时间、行情来源、合约、原始价格、成交价格、手续费、滑点和触发原因。

## 已知限制

日线历史回放无法重建盘中先后顺序；同一根 K 线同时触及多个价位时采用保守成交顺序。实时纸面模式受行情刷新频率影响，不等价于交易所逐笔撮合。历史保证金和手续费若上游没有逐日版本，仍会明确使用当前合约规格并在界面标记。
