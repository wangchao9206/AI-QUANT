# 真实期货移仓换月设计

## 目标

回测必须模拟可交易合约，而不是把主力连续价格当作可下单标的。主力切换时按真实的新旧合约价格完成“平旧仓、开新仓”，价格差只改变新仓成本基准与保证金占用，不能在换仓瞬间凭空记成盈利或亏损。

## 方案比较

1. 固定周期与固定升贴水：实现快，但换月日期和价差都是假设，拒绝采用。
2. 天勤日线主力映射 + 新旧合约双腿价格：使用 `query_his_cont_quotes` 的真实每日主力对应关系，并在切换日读取两个挂牌合约的真实开盘价。适合当前日线策略，采用。
3. Tick 级 TqSdk/TqBacktest 撮合：精度最高，但需要把所有策略重写为事件驱动，并依赖更重的历史数据权限。作为后续独立阶段，不在本次冒充完成。

## 数据流

`TqSdkBacktestDataProvider` 使用已配置的天勤凭据下载主连日线、每日标的合约映射、换月日新旧合约双腿日线，以及合约乘数、最小变动价位、保证金和手续费元数据。下载结果写入 `HISTORY_CACHE_DIR/tqsdk-roll`，同一交易日内重复回测直接读缓存。

每根 `KLineBar` 携带当天实际可交易的 `contract_symbol`。当相邻交易日的合约代码变化时生成 `RollEvent`，事件必须同时具备旧合约和新合约的真实开盘价；缺少任意一腿时，不允许用估算价补齐，数据集标记不完整并拒绝启用真实换月。

## 成交与记账

- 信号仍在已完成日线收盘后生成，下一交易日开盘执行。
- 滑点参数改为“跳”，实际价格偏移为 `slippage_ticks * price_tick`。
- 持仓按整数手计算：目标保证金预算除以单手保证金，向下取整。
- 开仓费在开仓时扣除，平仓费在平仓时扣除，不再在平仓时笼统扣双边费。
- 换月日如果策略本来就要平仓，只平旧合约，不先换月再平仓。
- 否则先按旧合约开盘对价平仓并结算真实持仓盈亏，再按新合约开盘对价开仓；新旧价格差作为可审计的期限结构信息展示，但不直接修改账户权益。
- 换月后按新合约成交价重置持仓成本和止损基准；保证金不足时只能缩减手数，不能生成负可用资金。

## 限制与安全边界

本模型是可审计的日线开盘成交模型，不是 Tick 级成交保证。天勤当前合约规格是真实供应商元数据，但历史手续费和历史保证金调整若上游未提供，只能使用请求参数或当前规格，并必须在结果限制项中披露。数据源断开、主力映射缺失或双腿价格不完整时返回明确错误，不回退到固定周期或固定价差。

## 验收

- 单元测试证明价差不直接记入权益、换月产生两腿成本、整数手数和保证金约束生效。
- 数据测试证明主力映射只在真实合约代码变化时生成换月事件，缺腿时拒绝伪造。
- API 返回换月合约、手数、双腿价格、价差、手续费与滑点成本。
- Docker 环境用真实 CJ 数据跑出至少一笔可审计的历史换月记录。
